# 一、三条不变的原则

```
1. 取数优先        取数 > 估值 > 界面 > 开源推广
2. 数字纯代码      模型只碰版面与解释，不碰数字
3. 一个阶段一个数   每阶段只认一个验收数字，不看"感觉好多了"
```

# 一之二、终点定义（2026-11-22 用户定，优先级高于下面各阶段的旧验收线）

```
① 文件级：哪类文件适合目前的解析方法   → 文字版 PDF + 非金融
② 字段级：哪些字段适合               → 三档：高置信 / 低置信 / 拒答
③ 符合①②的字段要 ≥99% 正确
④ 解析不出的文件、低置信字段         → 明确告诉用户人工检查
```

**从「尽量多解析」换成「能判就判，不能判就明说」。**

```
高置信   有外部对照源时核对一致；无对照源时要求内部证据一致
低置信   合并/母公司证据打架、或外部核对不一致 → 给候选值+页码，交人工
拒答     没抽到 / 文件级不适用 → 不硬给值
```

**两个数必须同时报**：高置信正确率 + 高置信覆盖率（拒答率）。
只报正确率会靠"大量拒答"刷指标。

**A/B 两档口径**：A 档有外部对照（上市公司），B 档无对照（私密材料，
**定档不看真值、评估才看**）。A 档的 100% 是平凡的，B 档才是真实水平。

## 不再为单家公司改全局判据（2026-11-22 回归教训）

为 688316 一家改「合并页裁决」判据 → 9 家公司退步 30 格。
**保留门槛：≥3 家改善 且 0 家退步；只为 1 家有效的改动不进主线。**
剩余失败进「已知个案清单」，不追求 100% 解析率。


**理由**：数据不可信时，估值算得再对也只是更快地得出错误结论。

**为什么排第一**：12 份 / 12 家公司 / 真值 100% / 方法已验证 8/8 —— 唯一能闭环的一格。

| 步骤 | 内容 | 工期 |

**A4 为什么必须在宣布达标之前**：现在的 10 家全是文字版、无金融、7/10 是创业板科创板，

# 四、变更规则（防止再换方向）

**只有三种情况允许调整这份路线：**

```
① 某个阶段的「验收数字」没达成 —— 是数字没到，不是"感觉不对"
② 方案可行性被证伪 —— 例如列角色在 >20% 的样本上失败
③ 用户明确要求改
```

**其他一切情况：不打断当前阶段。**

发现的新问题一律写进 `BACKLOG.md`，每周统一处理一次。
**"顺手修"从今天起禁止** —— 它没有度量兜底，改坏了也发现不了。
